# kmemo — 運用・改造スキル

## ファイル構成（触っていい場所）

| ファイル | 役割 | 編集 |
|---|---|---|
| `kmemo_config.php` | ユーザーの列挙 | **ユーザー追加はここだけ** |
| `kmemo.php` | 本体(画面・API・台帳) | 改造時のみ |
| `kmemo_data/*.json` | メモ(個人情報) | **直接編集禁止** |

## よくある依頼

### 「ユーザーを追加して」
```php
function kmemo_users() {
    return array(
        'kojima' => '$2y$10$...',
        'yamada' => '$2y$10$...',   // ← 1行足すだけ
    );
}
```
ハッシュは `php -r "echo password_hash('パスワード', PASSWORD_DEFAULT);"`。
ユーザー名は半角英数(ファイル名に使われる)。削除は行を消すだけ——次のアクセスから
締め出される(セッションが残っていても km_current_user() が弾く)。

### 「デモにしたい」
設定に `define('KMEMO_DEMO', true);`。画面に注意書きが出て、ログイン画面に
デモ用の資格情報を表示する。

### 「文字数上限を変えたい」
`KMEMO_MAX_CHARS`(既定200,000)。上げすぎると1回の自動保存が重くなる。

## 改造時の鉄則

1. **台帳の更新は km_update() のロックの中だけ。** 外で読んで書くと
   自動保存の連打で片方が消える。
2. **他人のメモに触れる経路を作らない。** 台帳はユーザーごとに別ファイル、
   保存/削除は「自分の台帳の中でIDを探す」実装になっている。この構造を保つ。
3. **入力の不備は4xxで返す。** 500で包むと外形監視が障害と誤判定する。
4. **タイトル欄を足さない。** 1行目=タイトルはこの製品の芯。欄を足すと
   Simplenote型の「考えずに書き始める」体験が壊れる。

php scripts/check_kmemo.php   # 26件全部通ること
