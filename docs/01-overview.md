# kmemo の設計

## 何を解いているか

メモを他社サービスに置くと、(1)アカウントの再認証に付き合わされる (2)サービス終了・
仕様変更でデータが人質になる、という2つの不安が残ります。kmemo は「Simplenoteの
使い心地(1行目=タイトル・自動保存・即時検索)を、自分のレンタルサーバーで」が主題です。

## 構成

- `kmemo.php` 1ファイル。前半=関数(台帳・タイトル導出・認証)、後半=画面とAPI
- `kmemo_config.php` にユーザーを列挙(kcaldavと同じ方式)。値は password_hash()
- 保存は `kmemo_data/notes_<user>.json`。**ユーザーごとに完全に別ファイル**なので、
  他人のメモが混ざる経路が構造的に無い
- 更新は km_update() の flock の中だけ。読んでから書くまでを同じロックに収める
- `kmemo_data/` には deny の .htaccess を自動生成(直接ダウンロード対策)

## タイトルは「持たない」

タイトル欄は無く、常に本文1行目から導出する(km_title)。Simplenoteと同じ思想で、
「タイトルを考える」という作業自体を無くすため。空メモは「(無題)」。

## 自動保存の作り

input イベント→0.7秒デバウンス→ ?api=save。加えて beforeunload と
visibilitychange(バックグラウンド化)でフラッシュする。保存失敗時は dirty を立て
直して「保存できていません」を表示(黙って捨てない)。

## 検証

`php scripts/check_kmemo.php`(26件)。要点は「他人のIDでは保存も削除もできない」
「長すぎる保存は4xxで断る」「データ置き場に.htaccessが生える」。
